## 审查结论（只读，以下未改代码）

- 鉴权与额度：结构正确。
  - 服务令牌用 `hmac.compare_digest`。
  - 邀请码 144 位、会话 256 位，库里只存 SHA-256。
  - CSRF 绑定会话并带过期时间。
  - 对话键带用户 id。
  - 预留按实际消息估算输入，长对话也不会少算钱。
  - Next.js 路由在读请求体前先查 Origin / Host / 类型 / CSRF / Cookie。
- `agent.serve` 和 `/api/chat` 只靠服务令牌加会话；`server`（8000）仍无鉴权，只听回环。两者都靠「只听本机 + Tailscale」兜底，这是已有设计。
- 风险，推断未验证：
  - `graph.run_tools` 只接住 ValueError、TypeError、KeyError、LookupError。实盘写库时间超过 `open_readonly` 的 10 秒等锁时，`sqlite3.OperationalError` 会让整轮出错：网站返回「服务出错」，命令行打印堆栈。没有复现。
- 风险，推断未验证：
  - 同一 thread 不限轮数。花费按实际消息预留，所以不会超额度，但对话很长时可能超出模型上下文、报错。
- `run_agent.bat`：`.env` 没填时 `agent.serve` 会退出，每 30 秒重启一次，每次在 `logs/agent.log` 追加一段报错。
- P4：已知的 NaN 缺陷（`docs/issues.md` 未解决）没改。G1 已用掉留出集，冻结后再改研究代码属于事后修改。
- P5（LoRA）：没做，要用户先定：
  - 用哪个 Qwen 模型、下载多大。
  - 是否换 CUDA 版 torch（本机有 RTX 4060 8 GB，现在是 CPU 版）。
  - 云端输出的使用条款。
