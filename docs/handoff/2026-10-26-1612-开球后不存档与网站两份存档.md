# 开球后不存档与网站两份存档

## 需求

用户批准三步计划（局域网部署相关文件和文档行先不上传）：

1. 临场档写快照、存档记对阵，提交时去掉部署行（已在 8480435）。
2. 修存档时刻：开球后不存档、存档与多家赔率记真实时刻、评分排除开球后的行。
3. 网站显示两份存档：首次存档（官方评分）+ 临场 `_t1` 存档（开球后主显示），标出亚盘线变化，单独提交。

只授权本地提交，未授权推送。

## 实际操作

- 第 2 步提交 `7a19cea`（v1.10.1，data 1.8.0 / review 1.7.0 / live 1.10.1）：`save_prediction(..., at=)` 在开球 ≤ 存档时刻时不存；`round_clock` 按轮开始时刻加单调时钟；`oddsportal.collect` 的 `fetched_at` 按实际抓取时刻，`timer` 可注入；`_scored_first` 不计 `generated_at >= kickoff_utc` 的行。`docs/issues.md` 记了一条已解决问题。
- 第 3 步：
  - `services/match_read.py` 的 `_first_archive(conn, id, near=True)` 取 `market_implied_t1`，两份都排除开球后才存的行。
  - 接口 `ArchivedPrediction` 加 `horizon` / `n_books` / `hours_to_ko`，`MatchDetail` 与 `RecentMatch` 加 `near_archived`。
  - 重新生成 `web/openapi.json`（`python -m server --openapi web/openapi.json`）和 `npm run api:types`。
  - 网站：`api-adapter.ts` 的 `lineMove` 写盘口变动。卡片开球后优先显示临场档并标明是哪份存档，详情页两份都列出。
- 盘口变动用词：最初写成「升盘 / 降盘」，用真实数据核对时发现弗赖堡对拜仁（主+1.50 → 主+1.25）会被说成「主队让更多」，是错的。已改为按让球方说：主队让球加深 / 变浅、受让变多 / 变少、让球方换边，并补了测试。
