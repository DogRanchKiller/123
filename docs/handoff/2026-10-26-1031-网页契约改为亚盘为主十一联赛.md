# 网页契约改为亚盘为主、11 联赛

## 需求

完善计划第 1 步：网页展示契约按报告字段改为亚盘为主，联赛扩到 11 个；只改结构和演示数据，不接后端。第 2–4 步（`services/`、`server/` FastAPI、前端接真实接口）未开始。

## 实际操作

- 新增 `web/src/features/match/leagues.ts`（11 联赛，顺序同 `live.LEAGUES`）、`asian.ts`（按 Python `ah_text` / `ah_pick_text` 格式化）、`asian-section.tsx`（卡片摘要 `AsianSummary`、详情块 `AsianBlock`）、`asian.test.tsx`。
- `types.ts`：`Prediction` 增加 `oddsSource`、`asian`（`AsianHandicap`，字段对应 `analysis.asian()`）；`league` 改为 `LeagueCode`。
- 详情和卡片先显示亚盘，再显示胜平负；首页卡片加「亚盘选择」行（`EntryPrediction.asianPick`），首页三格改为「11 个联赛 / 亚盘为主 / 首次存档」。
- 预测页联赛筛选改用 `LEAGUES`，存储恢复改用 `LEAGUE_CODES`；页面与 metadata 的「英超 · 德甲 · 西甲」改为 11 联赛说法。
- 成绩单 `ReviewRow` 改为数值字段，对应 `scorecard.live_report()`：亚盘场次 / 亚盘 Log Loss / 亚盘命中在前，胜平负指标在后，加同场对比 market_avg（差值 ± SE）；说明替换主模型只看胜平负、≥1000 场。
- 演示数据：原 5 场 ID、概率不变，补亚盘与赔率来源；新增一场土超 `demo-galatasaray-fenerbahce`（非推荐，排在最后）。
- 修了 `list-state.client.ts` 的滚动保存：进入详情时路由先切换并滚到顶，列表的 scroll 监听在卸载前仍会触发，把保存的位置写成 0。现在路径不是列表时不写。
- 文档：`docs/progress.md`（网站演示骨架小节、验收数字）、`docs/modules.md`（演示契约加亚盘块说明）、`docs/stack.md`（三联赛 → 11 个实盘联赛）。未升 `SYSTEM_VERSION`，Python 行为不变。
