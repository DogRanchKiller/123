# 补装httpx与Windows暂定核对

## 需求

用户：把缺的包装上；Python 3.12 / AMD64 先保留，在文档里写定，等 Windows 机拉取时由它自行判断；做完后等用户审核 P0，确认后再开始 P1。

「装缺的包」是用户明确授权给 `.venv` 补 `requirements.txt` 里已写、却没装的包，不是加新依赖；`agent-dev.md` §1「`.venv` 一个包都不加」指的是 ML 包，这次不涉及。

## 实际操作

1. 记下 `.venv` 当前 `pip freeze`，`pip install --dry-run -r requirements.txt -c <freeze>`：只会装 httpcore 1.0.9、httpx 0.28.1。
2. `.venv/bin/python -m pip install -r requirements.txt -c <freeze>`（锁住已有包版本），`pip check`。
3. 两个环境各跑 `python -m pytest tests -q`；核对 `.venv` 的 37 个包在 `.venv-ml` 里同版本。
4. `constraints-ml.txt`：删掉「.venv 里没有装 httpx」的注释，补钉 `httpcore==1.0.9`；`pip install --dry-run` 确认 `.venv-ml` 不需要变动。
5. 文档：
   - `docs/issues.md`：httpx 一条移到「已解决」，原因补上证据（`httpx` 由 2026-10-26 的 `7f2aba5` 加进 `requirements.txt`；Mac `.venv` 的 `pyvenv.cfg` 是 2026-10-24）。
   - `docs/agent-plan.md` §5：基线改写为「开始时 210 passed / 1 skipped，补装 httpx 后 218 passed」。
   - `docs/agent-dev.md` §3：决定 4 标「暂定 3.12 / AMD64」，新增小节「Windows 实盘机拉取后自行核对」（查版本和架构 → 一致就记录并改成已核对，不一致就按实际值重跑 `uv pip compile`；顺带核对 `.venv` 的 `pip check` 和 `pytest tests`；不在 Windows 上建 `.venv-ml`）。
   - `AGENTS.md` 两人协作一节：加一条指向这个小节，Windows 那边的 Agent 读规则时能看到。
   - `docs/progress.md`：P0 子项改成新的基线和「暂定」的写法。
