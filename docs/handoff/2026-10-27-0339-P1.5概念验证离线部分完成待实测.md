## 实际操作

- 分支 `agent/p15-poc`（从 `8b93a82` 切出）。P1 验收后对 `docs/progress.md`、`docs/handover.md` 的未提交修改也带到了这个分支上。
- `requirements-poc.txt`：langgraph 1.2.17、langgraph-checkpoint-sqlite 3.1.2、langchain-core 1.7.0、langchain-openai 1.7.2、langchain-anthropic 1.7.6。
  - 安装：`.venv-poc/bin/python -m pip install -r requirements.txt -r requirements-ml.txt -r requirements-poc.txt -c constraints-ml.txt`。
  - 之后跑了 `pip check`。
- 新增 `agent/poc/`：
  - `llm.py`：读 `.env` 里的 `AGENT_PROVIDER / AGENT_MODEL / AGENT_BASE_URL / *_API_KEY`。
    - 有两条路：`openai_compat` 用 `ChatOpenAI`；`anthropic` 用 `ChatAnthropic`，只写了接口。
    - SDK 自带重试设为 0，由 `call_model` 自己重试 1 次。
    - 用 httpx 事件钩子逐个数 HTTP 请求。
    - `describe()` 不输出密钥。
  - `graph.py`：方案第 8.1 节的流程 agent → tools → … → submit_answer → verify → render / 打回 / degrade。
    - 上限：`model_calls` 6、`tool_rounds` 4、`answers` 2、HTTP 12。
    - 结构化答案通过 `submit_answer` 工具提交，不依赖提供方的 response_format。
  - `facts.py`：verify 只查两条：文字里没有数字（含全角数字）；占位与事实一一对应，`tool_call_id` 必须是本轮调用过的。
  - `run.py`：命令行，可用 `--check`、`--estimate`、`--probe`、`--run [--limit N]`。
- 新增 `agent/eval/poc.jsonl`：20 条问题。
- 新增 `tests/test_agent_poc.py`：假模型（`FakeMessagesListChatModel` 子类）和 `httpx.MockTransport`，全部离线。
- `tests/test_agent_boundary.py`：`POC_THIRD_PARTY` 只对 `agent/poc/` 放行 langgraph、langchain_*、openai、httpx；扫描器自测里加了对应断言。
- `.env.example`：加 `AGENT_BASE_URL`，并说明 `AGENT_PROVIDER` 的两个取值。

## 证据

- `pytest tests`：
  - `.venv-poc`：260 passed。
  - `.venv`：235 passed / 2 skipped。多出的 1 个 skip 是 `test_agent_poc`，因为没有 langgraph。
  - `.venv-ml`：237 passed / 1 skipped。
- `football.db` 的 md5 前后都是 `961767381d788c206df8bb5a8edc1c6e`。
- `run --check`：provider / model / base_url 都为空，`key_set: false`，说明本机还没有 `.env`。
- `run --estimate` 是离线粗估，中文每字算 1 token，其余每 4 个字符算 1 token。
  - 工具返回按真实库各调一次算，共 1188 token。
  - 每题上限：输入 11706、输出 3000。
  - 20 题上限：输入 234120、输出 60000。
  - 典型猜测：输入 78300、输出 30000。
  - 未验证：真实分词器的计数，以及比赛多时 `list_upcoming` 的返回长度。
- 第 6 节五项（只对 LangGraph）：

| 项 | 结果 |
|---|---|
| 接 Claude / 本地 OpenAI 兼容接口 | 两者都有写法。OpenAI 兼容这条用 MockTransport 走通了真实的 ChatOpenAI → openai SDK → httpx，包括 500 之后重试。Claude 没有密钥，未实测；本机没装 Ollama，本地接口未实测。 |
| 结构化输出加打回重答的代码量 | `graph.py` 157 行加 `facts.py` 60 行。打回时，校验错误作为 submit_answer 的 ToolMessage 回给模型。测试覆盖了首次通过、重答通过、两次都不通过时降级。 |
| 状态持久化和中断恢复 | `SqliteSaver` 加 `interrupt_before=["tools"]`：停在执行工具前，关掉连接后用新图、新模型、同一个 thread_id 接着跑完（`test_checkpoint_resume`）。 |

| 次数上限与 token 用量 | 四个计数放在图状态里，各自判定，都有测试。用量从 `usage_metadata` 取，MockTransport 下与返回的 usage 一致。 |
